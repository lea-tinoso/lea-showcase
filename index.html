My loop, every build

Tech stacks change. The way I break a problem down stays the same. Every project, big or small, goes through these four steps with Claude Code as my pair.

  1. Explore

    Before touching code, I find out what's really there: the repo, the constraints, what the person actually wants.

    I ask Claude: read the codebase and tell me how this part works before we change it.

  2. Plan

    I write the approach down and argue with it. Weak spots are cheaper to fix in a plan than in a pull request.

    I ask Claude: propose a plan, then list what could go wrong with it.

  3. Build

    Small steps, each one reviewable. I steer, Claude types, and I read every diff like a reviewer would.

    I ask Claude: make the smallest change that proves the plan works.

  4. Verify

    Tests, screenshots, a real run. It isn't done when the code compiles. It's done when I've seen it work.

    I ask Claude: show me evidence that this works, not a summary saying it does.

The ladder is the "Agentic Coding Proficiency Journey" from a 15-minute talk by two Senior Staff Engineers at Airbnb ↗

  • Auto-approval inside a review gate.I run coding agents on auto-approval inside a review gate, not in place of one. Two independent reviewer agents must both pass before anything is pushed.
  • Parallel agents, models picked by cost.I run several agents in parallel, each in its own git worktree. A big model does the main work; small, cheap models do wide review sweeps.
  • About 3× more agent commits than mine.On my main project my coding agent has made ~390 commits to my ~120. My job has shifted from writing code to setting the guardrails it runs inside.
  • Two agent runners, bent to my workflow.I adapted two runners I didn't originally write, across ~250 commits: ticket limits per day, a hand-off when the agent refuses a task, and a draft-PR flow.
  • A "tech lead" agent, built from scratch.82 of 82 commits are mine. It watches a team's pull requests, posts reviews, runs in shadow mode before it's trusted to merge, and has a nightly loop that proposes improvements to its own rules. See the repo ↗
  • No custom MCP server yet.The ones I use are shared or third-party.
  • A user of the team skills library, not a contributor.I use a shared library of agent skills but have 0 commits there.
  • My leadership evidence is decisions, not code.Who reviews and merges whose PRs, how QA hands off to agents, and specs for team bots that others build.
  • Only my own commits.I counted commits authored by me and separated them from the commits my agents made under my identity.
  • Nothing my agents or teammates wrote.Not even inside tools I use every day.
  • Claude went first, then I corrected it twice.It had credited me for skills I never touched, and for creating bots I'd only adapted. Both corrections lowered the score. That's the point.

Next rung: build one small MCP server for a real team pain point, instead of having each agent scrape the same APIs separately.
